# Interviewer requirements verification

Scope: the local Short-Notes interviewer described in this conversation. Code inspection and deterministic regression tests verify the mechanisms below. They do not certify every model response or a full hour of live microphone use.

| Original requirement | Implementation and evidence | Boundary |
| --- | --- | --- |
| LLM + loop + tools + guardrails | Gemini adapter; runtime with six model rounds, scoped schemas, prompt/tool budgets and deadlines; tool-loop and rejection tests | Model judgments remain fallible; no arbitrary shell/code execution |
| Hub with individual specialist tasks and memories | `agent/hub.mjs` selects intro/theory/coding/review; each has prompt, permissions and private message/assessment history; handoffs carry explicit shared evidence | Specialists are sequential role instances, not four independent background processes |
| Subject-specific interview | Subject filters apply to question retrieval, notes, coding assignments and remembered assessments; all eight subjects have content/tasks | Follow-up relevance and difficulty are generated by the model |
| Start with tell me about yourself and drill into projects | Server greeting plus intro prompt and shared introduction dossier | Follow-up quality needs human-reviewed live evaluation |
| Theory questions, corrections and follow-ups | Theory prompt, repository retrieval and formative assessments; assessments retained as evidence | Prompts guide semantic correctness; tests cannot prove all explanations correct |
| Machine-coding round and helpful hints | One validated subject task, editable code, progressive hint prompt, 90-second inactivity offers | Offers require learner acceptance; inactivity is not automatically graded; code is reviewed as text |
| Roughly one hour with pause/resume | Server elapsed clock and intro 0–5, theory 5–30, coding 30–55, review 55–60; phase budget respects review boundary | Early ending and turn limits are supported; processing/retry delays can affect wall-clock duration |
| Short-term and long-term memory | Private specialist histories and hub handoffs; MongoDB session assessments retrieved across interviews | Same-subject bounded topic recall; no semantic search or spaced-repetition scheduler |
| Remind me when revisiting earlier weaknesses | Validated prior-memory reference, dated written/spoken reminder, latest verdict and improvement tracking | Topic identity, not guaranteed exact question matching |
| Voice conversation and smooth interruptions | Default automatic conversation loop, live ASR captions, finalized-only answers, incremental server TTS playback, pause/resume, bounded retries and stale-result guards | Browser captures/plays audio only; speech tools need Gemini quota. Noise affects pause detection. Alternating speech turns; interruption uses a button. No full-duplex or latency guarantee |
| Faster answer-to-speech handoff | Scoped evidence preparation avoids unnecessary retrieval round trips; role-specific prompts, concise speech, streamed PCM, and cached Replay | Model latency still varies. Text is shown after validation and atomic save; unsafe partial tool responses are not presented as final answers |
| Reliable persistence and recovery | Atomic MongoDB document saves, stale-write checks, idempotent turn retries, preserved drafts, insert-only JSON migration | Single local learner; no public account/authorization system |

## Corrections made during this verification

- Coding time estimates now stop at the 55-minute review boundary rather than including review time. Fractional remaining time is available to the specialist.
- When a timed transition occurs while answering the previous round's question, the user message retains its original phase and the assessment is stored under that phase's specialist memory.
- User transcript entries now carry action metadata. Code sent with hint/end requests is kept separate from actual answer submissions in review counts, including compatible handling of older sessions.
- Removed a prompt conflict between avoiding repeated questions and deliberately revisiting remembered weak topics.

## Validation and remaining acceptance work

The complete lifecycle regression covers introduction, theory assessment, coding assignment, a hint, code submission, review, completion, all three specialist handoffs, and private assessment ownership. Additional boundary tests cover timed transitions, round budgets, legacy evidence, memory, retries, tool budgets, and server speech transport, recording cancellation, transcription retry and playback. Latency regressions cover fragmented SSE, early PCM delivery, explicit completion, quota versus mid-stream errors, disconnection, shared speech concurrency, scheduled playback, cancellation of stale handoffs, completed-only Replay caching, scoped preparation, quota/overload failover and cooldowns, and the automatic UI cycle in both streaming and complete-WAV modes.

Run `npm run check` and the opt-in `npm run db:check` from `playground/`. The latter uses isolated synthetic records and a real MongoDB reconnect. Neither substitutes for an actual one-hour spoken interview. Remaining acceptance work: real microphone/echo behavior in the target browser, complete keyboard, narrow-layout, and light/dark visual review (desktop dark setup was inspected; the full visual matrix is still pending), a curated human-reviewed interview-quality dataset, and account/retention/spend controls before public deployment.
