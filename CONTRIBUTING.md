# Notes ka style

- Language — simple Roman Hinglish; technical names/code English mein.
- Format — `term — seedha meaning / zaroori catch`; ek bullet mein ek concept.
- Length — usually 5–15 bullets per topic group; wider chapters mein small headings use karo, long paragraphs nahi.
- Accuracy — short karte waqt scope, condition, complexity ya failure caveat mat hatao.
- Example — `var — function-scoped; reassign aur redeclare ho sakta hai.`
- Code — optional snippets `examples/<track>/` mein; chapter se relative link do.
- Sources — existing official source links preserve; version-sensitive naya claim verify karo.
- Metadata — chapter IDs, track, order, tags aur visual IDs stable rakho; minutes revision reading ke hisaab se.
- Navigation — `notes/curriculum.json` canonical hai; generated README manually edit mat karo.
- Interviews — canonical question data `playground/src/data/*Questions.js`; answers mein short fact bullets.
- Practice — code, outputs, runtime assumptions aur acceptance checks preserve karo.
- Chapter recall — `## Recall aur practice` mein `Sawal`, `Jawaab`, `Khud try karo` bullets; specific output/reasoning aur observable acceptance cases do.
- Practice questions — Recall ke baad `## Practice questions` section: kam se kam 5 questions, ek Easy aur ek Hard zaroor. Heading `### Easy · Title` (`Easy`/`Medium`/`Hard`), phir prompt (code/scenario), phir answer `<details>` + `<summary>Answer</summary>` ke andar. Answer mein output/reasoning, catch aur complexity ya test cases do; code answers run karke verify karo. Title chapter ke andar unique rakho — progress usi slug se save hoti hai.
- Depth — related edge cases aur failure conditions explain; same generic tips har chapter mein repeat mat karo.
- Source folders — har mapped JS/JSX/Java file mein short Quick revision bullets; code examples preserve karo.
- Audit — `node scripts/check-revision.mjs` format, duplicate labels, source-topic presence, chapter recall, graded practice sections aur interview answer length verify karta hai.
- Generation — root se `node scripts/sync-curriculum.mjs`, `node scripts/sync-interviews.mjs`, `node scripts/sync-priority-interviews.mjs`, `node scripts/sync-machine-coding.mjs`.
- Offline — `npm run check` build ke baad `offline:check` chalata hai (service worker lists, manifest, icons). App icon badalna ho toh `playground/public/favicon.svg` edit karke root se `node scripts/make-app-icons.mjs` chalao (macOS: built-in renderer use karta hai) aur PNGs commit karo.
- Link preview card — chapter, visual, answer ya flashcard counts badlein toh `docs/assets/social-card.svg` update karke root se `node scripts/make-social-card.mjs` chalao (macOS) aur `playground/public/social-card.jpg` commit karo. Script 1200×630 aur 300 KB se kam size check karta hai.
- Chapter index — chapter add karne, ya frontmatter/tags/practice questions badalne, ya interview question add karne ke baad `node scripts/sync-chapter-index.mjs` chalao. Yeh `playground/src/data/chapterIndex.json` banata hai (app ki pehli chhoti list: titles aur counts, text nahi); haath se edit mat karo. `npm run chapters:check` stale index par fail hota hai.
- Verify — `cd playground` phir `npm run check`; IDs, links, examples aur app checks pass hone chahiye.
- English chapter — `notes/en/<track>/<same-file>.md`; frontmatter IDs, code blocks, section count aur practice levels original jaise rakho. Headings `Understand it with an example`, `Recall and practice`; recall labels `Question`, `Answer`, `Try it yourself`.
- English check — `npm run i18n:check` structure verify karta hai aur coverage print karta hai; wording ki accuracy khud review karo.
- English helper — `node scripts/translate-chapters.mjs extract <track> [from] [to]` translatable lines `.i18n-work/seg/` mein nikalta hai; translated copy `.i18n-work/tr/` mein rakhkar `weave <track>` chalao. Code blocks aur structure automatically same rehte hain.
- English interview answers — `node scripts/translate-questions.mjs extract <track> [from] [to]` question, answer ki prose lines aur follow-up nikalta hai; translated copy `.i18n-work/tr/q-<track>-NN-NN.txt` mein rakhkar `weave` chalao, jo `playground/src/data/i18n/questions.en.json` likhta hai. Machine-coding question ka task text (`promptCode`: build contract + acceptance checks) alag se `extract-prompts <track>` se nikalta hai aur `.i18n-work/tr/p-*.txt` se weave hota hai. `stats` har track ka coverage dikhata hai. Naya question add karo toh uska English entry bhi add karo, warna woh Hinglish notice ke saath dikhega.
- Stage/title text — `notes/en/curriculum.json` (stages) aur `notes/en/chapters.json` (title + summary); naya chapter ya stage add karo toh dono update karo.
- UI text — component mein direct string nahi; key ko `playground/src/i18n/hinglish.js` aur `en.js` dono mein add karke `t('key')` use karo.
- Visual — metadata/frames `playground/src/data/visuals.js` ya `moreVisuals.js` mein, English text `visuals.en.js` mein; ID ko `src/lib/visualIds.js` mein add karo. Algorithm trace ko compute karo, haath se frames mat likho.
- Analogy — `playground/src/data/analogies.js`; `title`, `text` aur `catch` (analogy ki limit) dono languages mein zaroori.

- Topic coverage — equivalent source labels `scripts/revision-topic-aliases.json` mein map hain; naya alias sirf manually verified equivalent concept ke liye.
